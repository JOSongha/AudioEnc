## Why v5

Three retrospective findings on v4 (Stage-1, 100k step, 38h GPU) that v5 fixes:

| Finding | v4 effect | v5 fix |
|---|---|---|
| Projector capacity (~22M) bottleneck on multi-task fit | sound captioning BLEU-4 0.06, emotion ceiling ~0.40 even at composite-best ckpt | enlarge projector to ~70M (3×) |
| AudioSet / FSD50K captions were synthesised label-lists ("sound of X, Y") instead of the rich ontology descriptions originally intended | model learned the label-list format and bled it into Clotho/AudioCaps captioning, e.g. "sound of shing, clatter, liquid" or hallucinations | replace with ontology `description` per label (multi-caption list, Clotho/AudioCaps style) |
| Three emotion corpora had train ⊇ eval-split: DailyTalk last-5% dialogues, EmoV-DB Jenie speaker, RAVDESS Actors 21-24 (`build_emotion_*.py` did not honour `eval_source_emotion.py`'s held-out rules) | DailyTalk acc 0.96 / EmoV 0.99 / RAVDESS 0.96 reflected memorisation; only MELD-test was honest | builders now exclude the eval split before manifesting; train ∩ eval = 0 verified |

The base LM weights are unchanged (symlinked safetensors). Projector is reinitialised from scratch — `B3=scratch` from [`docs/v3_progress_log.md` §9-6](../v3_progress_log.md) already chosen for v4 vs v5 apple-to-apple comparison.

### 2. Loader patch (`ignore_mismatched_sizes`)

[`src/llamafactory/model/loader.py:194`](../../src/llamafactory/data/loader.py#L194):

```python
model = load_class.from_pretrained(**init_kwargs, ignore_mismatched_sizes=True)
```

Lets the resized projector load with mismatched key shapes (re-init from scratch) while LM weights load normally. No-op on shape-matching v3/v4 ckpts.

### 3. AudioSet / FSD50K caption format

[`scripts/v3_manifest/build_audioset.py`](../../scripts/v3_manifest/build_audioset.py) and [`scripts/v3_manifest/build_fsd50k.py`](../../scripts/v3_manifest/build_fsd50k.py):

```python
# v4 (replaced)
def synthesize_caption(human_labels):
    return f"sound of {', '.join(...)}"   # 2-3 word label list

# v5
def descriptions_for(human_labels, onto):
    """Returns one ontology description per label, deduped, in order."""
    return [onto[name]["description"] for name in human_labels if name in onto]
```

Sample rows now:

```jsonc

// FSD50K (was: {"captions": ["sound of electric guitar, guitar, music"]})
```

The loader's existing caption-pool sampling (one caption per epoch from the list; see [`omni_dataset.py:282-307`](../../src/llamafactory/data/omni_dataset.py#L282-L307)) handles the multi-caption layout the same way it does for Clotho / AudioCaps / Freesound, so no loader change is needed.

## Open: post-v5 follow-ups (not blocking launch)

- **Stage-2 LoRA still needed for captioning ceiling**: even with description-based env_sound captions, a Stage-1-only model emits multi-task tokens with imperfect format consistency. Stage-2 LoRA fine-tune on Clotho/AudioCaps would lift BLEU-4 from ~0.06 toward ~0.12 (Whisper-small Stage-2 result on the comparison table).
- **OOD emotion (SAVEE / JL-Corpus) ceiling at ~0.21-0.35** is intrinsic to cross-corpus SER (well-known hard problem), not something v5 alone fixes.
- **DAC-VAE encoder is still frozen** — projector-only Stage-1 keeps the v3 acoustic representation. If v5 still trails Whisper-small, the next axis would be unfreezing the DAC encoder for fine-tuning on the same mix.
